# SubmissionArchives Full Repository Audit

> Historical snapshot: this audit records the repository before the stabilization and hardening phases. The current architecture, commands, deployment flow, and supported maintenance scripts are documented in the root `README.md` and `scripts/README.md`.

Date: 2026-07-06
Scope: Full read-only audit of the SA project ahead of a reorganization/cleanup pass. No files were changed and nothing was committed or pushed as part of this audit.

Context: the project used to serve video/audio from Cloudflare R2. It has migrated to routing video and audio playback directly from YouTube to cut storage/hosting cost. Hosting itself has separately moved to a self-hosted Coolify deployment (not Cloudflare Pages/Workers). This document maps the current state of every route, script, data file, and asset folder so the reorganization can be planned with full visibility.

---

## 1. Migration status (the headline)

- **Video: fully migrated.** All 51 catalog entries have a `youtubeId`. `src/lib/mediaAssets.ts` refuses to fall back to Cloudflare for video and logs that "Cloudflare MP4 streaming is disabled due to CORS/grey screen issues" when no YouTube ID exists. Zero `.mp4` files exist anywhere under `public/`.
- **Audio: functionally migrated, not cleaned up.** All 101 audio entries have a `youtubeId` and `mediaAssets.ts` prefers YouTube, but an R2 fallback code path, R2 upload tooling, and R2-shaped data still exist and are wired up as if they might run again.
- **Hosting: moved to Coolify** (self-hosted, git-push-to-deploy). No Dockerfile is present despite a `.dockerignore` existing — Coolify is likely auto-detecting the build via Nixpacks. No GitHub Actions/CI exists.
- The two migrations (storage: R2 → YouTube, hosting: Cloudflare → Coolify) happened somewhat independently, which is why Cloudflare/R2 references linger in code, scripts, and docs even though hosting already left Cloudflare entirely.

Worth deciding: delete these routes entirely (recommended, since the migration work they supported is done) or keep them behind the existing gate and unify the auth check into one shared helper.
