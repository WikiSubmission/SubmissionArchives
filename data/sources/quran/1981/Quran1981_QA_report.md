## Two-source pipeline

This bundle combines two builds:

- The page-level files (`Quran1981_pages.csv`, `Quran1981_pages_layout.jsonl`, `Quran1981_complete.json`, `Quran1981_full_transcription.md`, `Quran1981_chapters.csv`, `Quran1981_appendices.csv`, `Quran1981_sura_index.csv`, `Quran1981_subject_index_lines.csv`) come from the original page-by-page OCR build (`build_quran1981_transcription.py`) run directly against the scanned PDF. These retain OCR block coordinates and page/printed-page numbers and are unchanged from the initial transcription pass.
- The verse-level files (`Quran1981_verse_index.csv`, `Quran1981_footnotes.csv`, `Quran1981_subheadings.csv`) are regenerated by `scripts/generate/parse_1981_md_to_csv.mjs` from a separately maintained, hand-correctable markdown source (`source-markdown/quran-complete.md`). This script hard-fails unless it finds exactly 6,236 unique verse IDs, so the verse text cannot silently drop or duplicate a verse.

The two builds are independent: the verse-level CSVs no longer carry `pdf_page_1981` / `printed_page_1981` / `chapter_number` columns. Anyone needing to map a verse back to its physical page should join through `verse_id` against `Quran1981_chapters.csv`'s chapter page ranges, not through the verse-index file itself.

## OCR handling (page-level bundle)

The book is a scanned facsimile. The page-level output retains both the scan's embedded OCR text and the original block/line coordinates, alongside a normalized reading text. Later-edition CSV wording was used only as an alignment/checking aid and was not copied over the 1981 wording.

Pages with no usable embedded OCR text: **1, 3, 4, 512, 557, 558, 560, 562**. These are covers, blank/endpaper/library pages, or the Arabic facsimile on PDF page 512. Targeted visual descriptions or manual Arabic transcription were added on pages: **1, 2, 3, 4, 5, 7, 512, 557, 558, 559, 560, 561, 562**.

## Accuracy status

The page-level bundle is a complete page-by-page structural transcription and not merely a prose extraction; every OCR block and line has placement coordinates, so any disputed wording can be checked directly against its exact page and bounding box. The verse-level bundle was rebuilt from the markdown source specifically to correct OCR-era wording defects (verified against the source PDF for spot-checked passages, e.g. 7:65, 9:123-129, 114:1-6) at the cost of the richer per-verse metadata carried by the original build. Both are retained side by side rather than merged, so consumers should pick the file that matches what they need: page placement, or clean verse text.
